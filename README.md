# Restaurant OS — فاتح أبو الغنية

نسخة Frontend Prototype عربية RTL لنقطة البيع وإدارة تشغيل المطعم. تعمل محليًا وتحتفظ بحالة النسخة التجريبية على الجهاز، مع ربط الطلبات وشاشة الفحم والورديات والخزنة والموظفين وسجل الرقابة.

## التشغيل

```bash
npm install
npm run dev
```

ثم افتح `http://localhost:3000`.

## حسابات العرض التجريبي

- المالك: `1234`
- المدير: `5555`
- الكاشير: `1111`
- شاشة الفحم: `2222`

لا تظهر الرموز داخل واجهة التشغيل. غيّرها قبل أي تجربة ميدانية.

## قواعد التشغيل المنفذة

- لا بيع أو مصروف أو صرف نقدي دون وردية مفتوحة.
- يبدأ النظام دون وردية افتراضية؛ يجب فتح الوردية يدويًا، وتستمر الوردية المفتوحة بعد إعادة تشغيل التطبيق حتى تقفيلها رسميًا.
- طرق الدفع المنفذة: كاش، بطاقة بنكية، وInstaPay، مع فصل كل طريقة في الوردية والتقارير.
- الدفع يقفل الطلب ماليًا، والتعديل اللاحق يتم كإلغاء أو مرتجع مع اعتماد وسبب.
- بون الفحم لا يعرض أسعارًا ويتزامن مع حالة الطلب.
- التقفيل Blind Cash Count ويستخدم مصدر حساب موحدًا للخزنة.
- السلفة تسمح برصيد سالب، أما السحب فلا يتجاوز رصيد الموظف.
- الساعة الإضافية تبدأ من 25 جنيه/ساعة من الإعدادات.
- التطبيق يساوي قيمة شيفت الموظف.
- المصروفات والسلف والسحب وحركات الخزنة تدخل في النقد المتوقع للشيفت.
- البيانات تحفظ تلقائيًا في الجهاز ويمكن تصديرها واستعادتها كنسخة JSON.
- النسخة الاحتياطية v3 تشمل بيانات التشغيل والخزنة والموردين والمخزون والرواتب والضرائب والدليفري معًا.
- استلام المشتريات يحدّث حساب المورد والمخزون، والرواتب المدفوعة ترتبط بالخزنة.
- الدليفري يمر بالتعيين والتوصيل والتحصيل وتسوية عهدة السائق.
- حذف الأصناف والأقسام يتحول إلى إيقاف/أرشفة بدل الحذف النهائي.

## فحص المشروع

شغّل `npm run check` لفحص TypeScript واختبارات الحسابات الأساسية.

## حدود هذه المرحلة

هذه نسخة Frontend مع بيانات محاكاة وحفظ محلي، وليست Backend إنتاجيًا. تكامل الطابعة الحرارية والبصمة والأجهزة المتعددة يحتاج خدمة Windows/Backend محلية وتعريفات الأجهزة الفعلية. زر الطباعة يستخدم نافذة طباعة النظام لاختبار تصميم المستندات.
