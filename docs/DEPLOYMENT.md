# تثبيت فالح على جهاز المطعم

ترتيب الخطوات مقصود: قاعدة البيانات، ثم الخدمة، ثم الحسابات، ثم المخزون.

---

## ١. الخدمة (السيرفر يقوم مع الجهاز)

افتح PowerShell بـ **Run as Administrator**:

```
E:\falah-restaurant\Falah-Restaurant-CSharp\tools\install-falah-service.ps1
```

الاسكربت بينشر السيرفر في مجلد ثابت (`E:\falah-restaurant\FalahServer`)، وينشئ خدمة
`FalahServer` **معتمِدة على SQL Server** عشان تقوم بعده مش قبله، ويضبط إعادة التشغيل
التلقائي عند الفشل (بعد ٥ ثوانٍ، ٥ ثوانٍ، ثم كل دقيقة، والعدّاد بيتصفّر كل يوم)،
ثم يشغّلها ويتأكد إنها بتردّ.

للإلغاء: نفس الاسكربت بـ `-Uninstall`.

**لو الخدمة مش بتقوم:** السبب بيتكتب في سجل أحداث ويندوز برسالة صريحة تقول إن
تهيئة قاعدة البيانات فشلت وعلى أنهي خادم وقاعدة — من غير أي بيانات اعتماد.

```
Get-EventLog -LogName Application -Newest 20 | Where-Object { $_.Message -like "*فالح*" }
```

## ٢. النسخ الاحتياطي التلقائي

**شغّال جوه السيرفر** — مفيش مهمة مجدولة تتثبّت ولا حساب تشغيل منفصل يتظبط.

اتاخد القرار ده عن قصد بدل Task Scheduler: النسخة اللي بياخدها السيرفر بتتسجّل في
جدول النسخ الاحتياطي بتاع البرنامج، فبتظهر في **شاشة النسخ الاحتياطي** وفي **لوحة
المتابعة** («آخر نسخة احتياطية: من كام ساعة» + حالة التحقق). نسخة بتاخدها مهمة
مجدولة من برّه مكانتش هتظهر في أي شاشة — والمطلوب صراحةً إن المالك يشوف آخر نسخة
ناجحة من داخل البرنامج.

**السلوك:**
- بيسأل كل **٣٠ دقيقة**: «آخر نسخة ناجحة عدى عليها أكتر من **٢٠ ساعة**؟»
  بالعمر مش بالساعة، عشان ماكينة المطعم بتتقفل بالليل ومنبّه ٣:٣٠ كان هينام على كل نسخة.
- بيتحقق من كل نسخة بـ `RESTORE VERIFYONLY` بعد ما ياخدها.
- **الاحتفاظ:** أحدث **٦٠** نسخة، **وبيرفض يمسح آخر نسخة متحقَّق منها مهما كان عمرها**.
- الفشل بيتسجّل في السجل وفي سجل التدقيق بدرجة «حرج».
- منسوب لفاعل نظام («النسخ الاحتياطي التلقائي») مش لاسم مدير.

**المجلد:** `E:\falah-restaurant\Backups` (`Backup:DefaultDirectory`).
لازم حساب خدمة SQL Server يقدر يكتب فيه — **SQL هو اللي بيكتب الملف مش البرنامج**.

**الإعدادات** — `appsettings.json`:
```json
"Backup": {
  "DefaultDirectory": "E:/falah-restaurant/Backups",
  "Automatic": { "Enabled": true, "MaxAgeHours": 20, "CheckIntervalMinutes": 30,
                 "KeepCount": 60, "StartupDelaySeconds": 90 }
}
```

**نسخة خارج الجهاز:** الاحتفاظ ده على نفس القرص. قرص المطعم لو باظ، باظ بالنسخ.
انسخ مجلد `Backups` على هارد خارجي أو سحابة بشكل دوري — **ده خارج نطاق البرنامج**.

## ٣. الحسابات الحقيقية

من شاشة «المستخدمون والصلاحيات»، بالترتيب ده:

1. **حساب المالك أولاً** — اختر الدور «مالك» من القائمة.
   ده الحساب الوحيد اللي **لا يُعطَّل ولا تُعدَّل صلاحياته** — مفتاح الطوارئ.
   النظام بيسمح بواحد فقط، ولو اتعمل مش هيسمح بتاني.
2. حساب لكل مدير وكاشير حقيقي، برقم سري خاص بيه.
3. **جرّب الدخول بكل حساب** قبل الخطوة اللي بعدها.
4. بعد التأكد، **عطّل مستخدمَي الديمو** (`أحمد الكاشير` و`مدير المحل`).

**حماية مبنية في النظام:** أي محاولة تشيل آخر مستخدم قادر على إدارة المستخدمين —
بسحب الصلاحية أو بالتعطيل — هتترفض برسالة واضحة. من غيرها كان ممكن النظام يتقفل
على نفسه بلا طريق رجوع.

الرمز السري: من ٤ لـ ٦ أرقام، والرقم المكرر بالكامل مرفوض.
