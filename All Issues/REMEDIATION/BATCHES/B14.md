# B14 — WinUI status casing (payroll screen, delivery board)

**Issues:** UI-0028, UI-0031 · **Started:** 2026-11-06 · **Depends on:** B02 (same payroll status vocabulary)

## Analysis (falah-analyst)

**Verdict: READY.** Client-only; no server, DTO or migration change.

### UI-0028 — still present
- The server sends payroll run statuses in lower case (`draft`, `calculated`, `reviewed`, `approved`, `paid`, `cancelled`).
- `src/Falah.Client.CashierWinUI/ViewModels/PayrollViewModel.cs:112-118` (`NextStatus`) and `:129` (`IsApprovedAndUnpaid`) compare against the capitalised names. As a result:
  - no "next step" is ever offered for a real run;
  - the pay dialog never opens for an approved run.
- Existing client tests pass only because their fixtures use the capitalised spelling: `FinalVerificationTests.cs:208,222` and `ManagementWriteSafetyTests.cs:63,184,189,192`.

### UI-0031 — new, folded into this batch (orchestrator, 2026-11-06)
- **Client:** `DeliveryViewModel.cs:73,77` compares `ElectronicPaymentStatus == "Pending"`.
- **Server:** stores and sends `"pending"`:
  - `OrderEnumMapping.cs:60`;
  - passed through unchanged by `DeliveryQueryService.cs:73,91`.
- **Result:** the delivery board never flags an unconfirmed transfer, and labels it "تحصيل عند التسليم".
- **Stale doc comment:** `DeliveryRequests.cs:72` says "Pending".

### Fix
- **PayrollViewModel:** add
  ```csharp
  private string? SelectedRunStatus => SelectedRun?.Status?.ToLowerInvariant();
  ```
  - `NextStatus` and `IsApprovedAndUnpaid` switch on it with lower-case literals.
  - `NextStatus` returns the server's lower-case value.
- **DeliveryViewModel:** use `string.Equals(Delivery.ElectronicPaymentStatus, "pending", StringComparison.OrdinalIgnoreCase)` in both `PaymentStateLabel` and `IsPaymentUnconfirmed`.
- **DeliveryRequests.cs:72:** correct the doc comment to `"pending"`.

### RED tests (Falah.Client.Tests)
- `FinalVerificationTests.Payroll_offers_the_next_step_for_a_run_in_the_servers_casing`: a Theory over draft, calculated and reviewed.
- `Payroll_opens_the_pay_dialog_for_an_approved_run_in_the_servers_casing`.
- `Payroll_advances_a_server_cased_draft_run_by_exactly_one_step`.
- **Guard** (green before and after): `Payroll_offers_nothing_for_a_paid_or_cancelled_run`.
- `Delivery_board_flags_an_unconfirmed_transfer_as_the_server_spells_it`.
