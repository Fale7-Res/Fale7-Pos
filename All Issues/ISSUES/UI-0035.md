## Reproduction and cause

Native ShiftsView with an owner session, an empty main treasury and a long connection-error message; opening or approval-step closing at short content heights. The primary button falls outside the view. Automated WinUI geometry reproduced 8 failures out of 36 Light/Dark cases; see artifacts/codex-takeover-20261108/native-shifts-red/Falah.Client.CashierWinUI/results.json and its captures.

The modal overlay grids had no Grid.RowSpan, so they were measured inside the page's Auto header row. Opening had no bounded scrolling body; closing placed actions within scrollable form content. MaxHeight alone did not bind either dialog to the available page height.

## Change

Both overlays span both page rows. Dialogs have bounded header/body/footer rows, a scrolling field body and persistent error/action footer, with a scroll hint when additional fields are outside the visible body. Original commands, counting/approval visibility, authorization and monetary logic are preserved. Stable AutomationIds were added for cancel, recount and shift-name controls.

- Expected cash is not visible during counting; the cashier cannot see the main treasury balance.

- No server policy, database schema, accounting behavior or production data was changed for this defect.
