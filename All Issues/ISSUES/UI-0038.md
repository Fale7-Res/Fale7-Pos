## Reproduction and cause

Overlay modals in both clients closed only with their X or Cancel button. Escape did nothing.

## Change

- `ModalHeaderView` (both clients): its close button has an Escape keyboard accelerator that runs the same close command.
- Accelerators in collapsed overlays are not processed, so only the open modal reacts.
- A modal whose close command is disabled (for example during an unresolved operation) still ignores Escape.

## Evidence and limits

- Native: `artifacts/claude-20261107/ui/controls/pos-11-after-escape.png`; the shift statement dialog also closed with Escape during the UI-REQ-002 run.
- Limit: not every modal was opened and closed with Escape individually.
