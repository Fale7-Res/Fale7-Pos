## Fix 2026-11-22 (owner decisions)

Owner decision 2026-11-22: normal rounding. CalculateLateDeduction / CalculateOvertimeAmount round half away from zero. Tests: PayrollRulesTests.

## Fix 2026-11-25 (audit: exact arithmetic)

The 2026-11-22 fix changed the rounding mode but still multiplied rate x hours x multiplier in `double`. For a
multiplier not exact in binary (1.15 and the like, which the owner can type in settings) the exact half came out as
57.4999... and was rounded down: one piastre short. `PayrollRules.HalfPiastreUp` now multiplies in `decimal` (the
double-to-decimal conversion keeps 15 significant digits, so 1.15 is exactly 1.15m); signatures and stored settings
are unchanged; the rounding rule is unchanged. A value too large for decimal now fails the request (nothing saved)
instead of posting a garbage amount.

Tests: `PayrollRulesTests.Overtime_rounds_half_a_piastre_up_for_a_multiplier_not_exact_in_binary` (3 cases) and
`Late_deduction_rounds_half_a_piastre_up_for_a_multiplier_not_exact_in_binary` seen red (57 for 58, 103 for 104),
then green. Domain 612/612. `AttendanceVerticalSliceTests`, `EmployeeVerticalSliceTests`,
`PayEmployeeVerticalSliceTests`, `PayrollVerticalSliceTests` 95/95 (scratchpad copy of the tree; a running
`Falah.Server` locked `src/Falah.Server/bin`).
