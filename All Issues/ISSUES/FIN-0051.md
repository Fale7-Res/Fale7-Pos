> The defect is present in current source as described.

## 1. Original source references

Remediation loop, batch B05 analysis (All Issues/REMEDIATION/BATCHES/B05.md).

## 2. Affected components

Delivery transitions; order cancellation endpoints; RefundOrderHandler (after B05)

## 3. Current code evidence

- `DeliveryTransitions` allows New/Preparing/Ready → Cancelled, but no handler or endpoint uses that transition.
- Pending electronic orders can be cancelled (`/api/orders/cancel-pending-electronic-payment`).
- Dispatched COD orders that fail or return are voided (`RecordDeliveryResultHandler.cs:133-161`, `VoidUndeliveredCashOnDelivery`).
- After B05 (owner decision 2026-11-06), refunds of an uncollected COD order are refused.

## 4. Relevant historical evidence

Owner decision 2026-11-06: "uncollected orders are voided/cancelled instead" (docs/REMEDIATION_PLAN.md § Decisions).

## 5. Expected behaviour

A COD order cancelled before dispatch (customer changes their mind) can be voided, with stock disposition and custody closure.

## 6. Actual code-supported behaviour

No path exists. The order stays open, and after B05 it can be neither refunded nor cancelled.

## 7. Root cause

A cancellation transition exists in the delivery state machine without a command.

## 8. Business impact

Phantom open orders; sales overstated until handled off-system; close blockers or custody may be affected.

## 9. Reproduction / failure scenario

Take a COD delivery order; the customer cancels before the driver leaves.

## 10. Existing safeguards

None identified beyond those noted in the evidence.

## 11. Missing safeguards

A cancel/void command for undispatched COD orders.

## 12. Recommended remediation

Add a manager-authorised void for undispatched delivery orders. It reuses OrderStockDisposition (prepared → waste, not prepared → restore) and sets the delivery to Cancelled. The permission is an owner decision.

## 13. Alternative approaches

Allow the existing failed-delivery path to be recorded before dispatch.

## 14. Required regression tests

Void an undispatched COD order: the order is cancelled, stock is disposed, it is not counted as a sale, and there is no custody.

## 15. Related issues

[FIN-0007](FIN-0007.md); [FIN-0036](FIN-0036.md)

## 16. Dependencies and prerequisites

Owner: who may void before dispatch.

## 17. Acceptance criteria

An undispatched COD order can be voided through the system.

## 18. Remaining uncertainty

The delivery state machine was read by the analyst; the endpoint search was not exhaustive.

## Fix 2026-11-22

Owner decision 2026-11-22, implemented: POST /api/orders/cancel-undispatched-delivery (CancelUndispatchedDeliveryHandler) cancels an unpaid cash-on-delivery order while its delivery is New/Preparing/Ready, inside its own open business day, with delivery_override or a manager approval, a reason and a stock disposition; replays by request id. Cashier delivery board: "إلغاء الطلب" button and dialog. Tests: OrderVoidDispositionTests (4 new; RED: route missing), DeliveryCancelBeforeDispatchTests (client, 7).
