> The defect is present in current source as described.

## 1. Original source references

Remediation loop, batch B07 analysis (All Issues/REMEDIATION/BATCHES/B07.md). The orchestrator confirmed on 2026-11-06 that the cited route handlers take no HttpContext and so carry no gate.

## 2. Affected components

Program.cs delivery driver account and statistics routes

## 3. Current code evidence

- `src/Falah.Server/Program.cs:1434` (`/api/delivery/drivers/{driverId}/account`) has no permission check.
- `src/Falah.Server/Program.cs:1442` (`/api/delivery/drivers/{driverId}/statistics`) has no permission check.
- The comment at `:2519-2523` records that the reference app gated driver accounts behind `reports_view`.

## 4. Relevant historical evidence

The reference app (ported) gated driver accounts as aggregate financial figures.

## 5. Expected behaviour

Only `reports_view`, `delivery_manage` (custody settlement) or `all` holders read driver custody money.

## 6. Actual code-supported behaviour

Any authenticated session receives the data, including a print agent or an HR-only account.

## 7. Root cause

The gate was not ported for these two routes.

## 8. Business impact

Cash-custody figures are visible to tills and station accounts.

## 9. Reproduction / failure scenario

Call GET /api/delivery/drivers/{id}/account with a cashier session: 200.

## 10. Existing safeguards

Session authentication only.

## 11. Missing safeguards

A permission gate placed first in each route.

## 12. Recommended remediation

Gate on `reports_view` or `delivery_manage`, with the gate first. Confirm which screen calls these routes before choosing.

## 13. Alternative approaches

None.

## 14. Required regression tests

Integration test: a cashier gets 422 and a `reports_view` user gets 200.

## 17. Acceptance criteria

Only the intended holders read driver custody money.

The calling screens have not been traced exhaustively; confirm them before choosing the permission.
