## Remediation record — 2026-11-07 Phase 1 (Claude)

Version tested: b3071be + working tree (diff fingerprint 20154C06992970FB at Phase 0; Phase 1 edits listed per issue).

Re-read 2026-11-07: SaveCashCountHandler.cs:41-42 still compares against request.ExpectedPiastres. Fixing it requires choosing WHICH system balance a business-day count is compared with (the drawer, which holds nothing once every shift has closed; the main treasury cash; or the shift's expected cash). That defines a financial control, so it is parked as an owner/accountant question (docs/ASSESSMENT.md). No code change.

## Fix 2026-11-22 (owner decisions)

Owner decision 2026-11-22: a business-day cash count is compared with the expected cash of the shift drawer (ShiftReconciliation.ComputeExpectedCashAsync), never with the main treasury or a typed figure. SaveCashCountHandler uses the request's shift or the latest open shift and refuses when none is open; the till no longer sends an expected figure and shows the server's. Tests: BusinessDayCloseVerticalSliceTests (+3).
