> The defect is present in current source as described.

## 1. Original source references

Copilot register FIN-015; PRODUCTION_RESILIENCE_AUDIT/06 CI-01

## 2. Affected components

CheckoutOrderHandler; CloseShiftHandler

## 3. Current code evidence

src/Falah.Infrastructure/Orders/CheckoutOrderHandler.cs:47-49 checks shift Open with an AsNoTracking read before its transaction (:145) and never re-reads it; src/Falah.Infrastructure/Shifts/CloseShiftHandler.cs:62-63 locks the shift row (UPDLOCK, ROWLOCK, HOLDLOCK) — checkout does not contend for it.

## 4. Relevant historical evidence

No additional historical evidence beyond the sources listed.

## 5. Expected behaviour

A sale is either refused or included in the close.

## 6. Actual code-supported behaviour

Interleaving: checkout reads Open → close commits handover → checkout commits → cash in drawer not in any handover.

## 7. Root cause

Admission check outside the money transaction (check-then-act).

## 8. Business impact

Cash discrepancy and unreconciled sale.

## 9. Reproduction / failure scenario

Cashier rings a sale while the manager closes the shift.

## 10. Existing safeguards

None identified beyond those noted in the evidence.

## 11. Missing safeguards

Shift lock/revalidation inside checkout transaction.

## 12. Recommended remediation

Inside the checkout transaction, re-read the shift with UPDLOCK and refuse if not Open.

## 13. Alternative approaches

Shift row rowversion checked at commit.

## 14. Required regression tests

Concurrency test with a barrier between the shift read and commit.

## 16. Dependencies and prerequisites

None.

## 17. Acceptance criteria

Concurrent close+checkout never yields a sale in a closed shift.

## 18. Remaining uncertainty

Race window size unmeasured.
