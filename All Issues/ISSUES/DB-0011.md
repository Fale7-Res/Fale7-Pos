**Evidence.** Full current-source integration run: HostHardeningTests.A_failure_while_authenticating_returns_the_handled_error_with_a_reference failed (Expected 500, Actual 503). Root cause (B36 draft): DatabaseActivityScope.EnterRequestAsync treated DATABASEPROPERTYEX(...,'UserAccess') = NULL (database missing/unreachable) as maintenance.

**Fix.** Only a real non-MULTI_USER access mode is maintenance; NULL lets the request reach the exception handler (500 + reference).

**Tests.** RED in the full current-source integration run (artifacts/claude-20261107/full-integration.log) and, for SEC-0035, again in isolation. GREEN: HostHardening, PinChoiceOracle, DatabaseMaintenance, PhysicalRestore, UserManagementVerticalSlice, LoginPinGuessing, ApprovalPinGuessing, LoginInfrastructureFailure, TransportSecurity = 105/105 in 14 m 5 s (artifacts/claude-20261107/regress-fix.log, trx regress-fix.trx). The same run also covers the fixture correction that made the 15 LoginPinGuessingTests fail with 400: FalahApiFactory now presents simulated non-loopback LAN clients as HTTPS, as real ones must be after B35; the transport guard itself is unchanged and TransportSecurityTests still pass.
