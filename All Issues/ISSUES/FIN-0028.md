## 1. Original source references

Copilot register FIN-033; INDEPENDENT_AUDIT (BCL check); PRODUCTION_RESILIENCE_AUDIT UH-06 (DST end hypothesis)

## 2. Affected components

BusinessClock.UtcRangeForBusinessDate and its 16 call sites

## 3. Current code evidence

src/Falah.Domain/Common/BusinessClock.cs:35-41 passes local midnight to TimeZoneInfo.ConvertTimeToUtc. A read-only BCL check (Windows PowerShell 5.1) showed IsInvalidTime(00:00)=True for 2025-04-25, 2026-04-24, 2027-04-30 in "Egypt Standard Time" and ConvertTimeToUtc throws ArgumentException. No DST test exists (tests/Falah.Domain.Tests/BusinessClockTests.cs has 5 facts; :33 assumes a winter offset).

## 4. Relevant historical evidence

Copilot overstated the scope as "every API endpoint"; BusinessDate() does not throw.

## 5. Expected behaviour

Valid 23-hour range on the DST start date.

## 6. Actual code-supported behaviour

Reports/queries for the DST start date and the day before throw.

## 7. Root cause

Local midnight does not exist on that date.

## 8. Business impact

Reports, payroll ranges and ledgers fail on that date; next occurrence 2027-04-30.

## 9. Reproduction / failure scenario

Owner opens the daily report for 2027-04-30.

## 10. Existing safeguards

None identified beyond those noted in the evidence.

## 11. Missing safeguards

IsInvalidTime handling; DST tests.

## 12. Recommended remediation

If local midnight is invalid, use the first valid instant (00:00 → 01:00); add DST start/end tests.

## 13. Alternative approaches

No meaningful alternative identified.

## 14. Required regression tests

Domain tests for 2026-04-24, 2027-04-30 (and previous days), and DST end (contiguous 25-hour day).
