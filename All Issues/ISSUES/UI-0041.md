## Reproduction and cause

- **Reproduction:** in the POS, choose "استلام من المطعم" with no time set. The editor showed the date "1/1/1926" and the time "0 : 00", as if a time had been booked (`pos-pass-after-sale` state; the UIA value of `Pickup_Date` was "1/1/1926").
- **What the view model held:** `PickupDate` and `PickupTime` are null. Saving produced no time, so this was display only. It still told the cashier something false, and invited them to "correct" a time that was never set.
- **Cause:** a classic `{Binding}` delivered the null to CalendarDatePicker and TimePicker as a default value. The calendar then clamped it to its MinDate (today − 100 years). A pass-through converter did not change this; that was tried and verified natively.

## Change

- **`PickupDetailsView`:** the two pickers are no longer bound. Code-behind copies the view model values into them, where a null stays null, and writes `DateChanged` and `SelectedTimeChanged` back to the view model.
- **Arabic placeholder:** the date picker shows "اختر التاريخ".
- **Unchanged:** the view model, its validation and the server rule.

## Evidence and limits

- **Native, before:** UIA value "1/1/1926".
- **Native, after:** the pickers show their placeholders (`artifacts/claude-20261107/ui/controls/pos-pickup-placeholders.png`).
- **Round trip:** picking 9 Nov writes it to the view model. Reopening the editor shows 11/9/2026, and saving with a date but no time is refused with "موعد الاستلام يحتاج التاريخ والوقت معًا" (`pos-pickup-date-only.png`).
- **Test:** `PickupPickerBindingTests` keeps the binding from returning.
- **Limit:** the TimePicker placeholders ("hour", "minute") come from the Windows display language. WinUI offers no property to set them, so on an Arabic Windows they will be Arabic.
