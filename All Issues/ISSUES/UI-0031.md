## 1. Original source references

Remediation loop, batch B14 analysis (All Issues/REMEDIATION/BATCHES/B14.md). The orchestrator confirmed the cited lines on 2026-11-06.

## 2. Affected components

DeliveryViewModel (PaymentStateLabel, IsPaymentUnconfirmed); DeliveryRequests doc comment

## 3. Current code evidence

- `src/Falah.Client.CashierWinUI/ViewModels/DeliveryViewModel.cs:73,77` compares `Delivery.ElectronicPaymentStatus == "Pending"`.
- The server stores and sends lower case: `src/Falah.Infrastructure/Orders/OrderEnumMapping.cs:60` (`ElectronicPaymentStatus.Pending => "pending"`). `src/Falah.Infrastructure/Delivery/DeliveryQueryService.cs:73,91` passes the stored value through unchanged.
- `src/Falah.Application/Delivery/DeliveryRequests.cs:72` documents the value as "Pending", which is wrong.

## 4. Relevant historical evidence

The same casing mismatch exists for payroll statuses (UI-0028). The server side already guards both spellings in one place (`OrderAutoPrintService.cs:63-64`).

## 5. Expected behaviour

An order whose InstaPay or wallet transfer is not yet confirmed is shown on the delivery board as "تحويل لم يُؤكَّد" and flagged as unconfirmed.

## 6. Actual code-supported behaviour

The comparison never matches, so the order is labelled "تحصيل عند التسليم" (collect on delivery) and is not flagged.

## 7. Root cause

The client literal differs from the server's wire spelling, and no test fixture uses the server spelling.

## 8. Business impact

A dispatcher can hand a driver an order whose transfer was never confirmed. The driver is then told to collect cash for an order the customer believes is paid, or nothing is collected.

## 9. Reproduction / failure scenario

1. Take a delivery order paid by InstaPay and leave it unconfirmed.
2. Open the delivery board. The order shows "تحصيل عند التسليم".

## 10. Existing safeguards

Business-day close blocks while pending electronic payments exist (`BusinessDayCloseEvaluator.cs:32`). The kitchen and receipt printouts mark pending payment.

## 11. Missing safeguards

A case-insensitive comparison, and a client test using the server's spelling.

## 12. Recommended remediation

Compare with `string.Equals(..., "pending", StringComparison.OrdinalIgnoreCase)` in both properties, and correct the doc comment.

## 13. Alternative approaches

Expose a boolean `ElectronicPaymentPending` on the delivery DTO (additive), as the print DTOs already do.

## 14. Required regression tests

Client test: a delivery whose ElectronicPaymentStatus is "pending" is labelled unconfirmed and `IsPaymentUnconfirmed` is true.
