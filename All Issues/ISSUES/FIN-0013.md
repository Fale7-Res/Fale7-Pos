> The defect is present in current source as described.

## 1. Original source references

Copilot register FIN-CAND-CLOSEDAY-ADMISSION-001

## 2. Affected components

BusinessDayGate; all money handlers; CloseBusinessDayHandler

## 3. Current code evidence

src/Falah.Infrastructure/BusinessDay/BusinessDayGate.cs:14-29 (plain read); called before each transaction, e.g. src/Falah.Infrastructure/Treasury/DepositHandler.cs:58 vs :60, AddExpenseHandler.cs:69/70, SafeDropHandler.cs:58/59; CloseBusinessDayHandler.cs:64 takes no lock that these commands contend for.

## 4. Relevant historical evidence

No additional historical evidence beyond the sources listed.

## 5. Expected behaviour

No movement posts into a closed day.

## 6. Actual code-supported behaviour

A command that passed the gate can commit after the close snapshot.

## 7. Root cause

Gate outside the money transaction; no day-state lock.

## 8. Business impact

Closed day's live figures change after close; snapshot no longer matches.

## 9. Reproduction / failure scenario

Deposit submitted while manager closes the day.

## 10. Existing safeguards

Close blockers prevent closing with open shifts / pending electronic.

## 11. Missing safeguards

Day-state revalidation under lock.

## 12. Recommended remediation

Re-check the day state with UPDLOCK on the business-day row inside each money transaction; close takes the same lock.

## 13. Alternative approaches

No meaningful alternative identified.

## 14. Required regression tests

Interleaving test close vs deposit.

No movement with a closed day id after close.
