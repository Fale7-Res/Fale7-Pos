## 1. Original source references

Remediation loop, batch B05 analysis (All Issues/REMEDIATION/BATCHES/B05.md).

## 2. Affected components

CashierViewModel.Refund (CanRefundOrder); OrderDetailsDto

## 3. Current code evidence

- `src/Falah.Client.CashierWinUI/ViewModels/CashierViewModel.Refund.cs:20-21` requires `IsPaid: true`.
- For cash-on-delivery orders, `Order.IsPaid` stays false for the order's whole life (`src/Falah.Domain/Reports/SalesRules.cs:54-58`). Collection is recorded by driver-custody settlement instead.

## 4. Relevant historical evidence

After B05 the server allows refunds of settled COD orders (owner decision 2026-11-06).

## 5. Expected behaviour

The till offers a refund for a COD order once its cash has been settled.

## 6. Actual code-supported behaviour

The refund action is hidden for every COD order.

## 7. Root cause

The client uses IsPaid as its "collected" signal; COD collection lives in delivery custody.

## 8. Business impact

Settled COD orders must be refunded off-system.

## 9. Reproduction / failure scenario

Look up a delivered and settled COD order at the till: no refund button.

## 10. Existing safeguards

The server rule (B05).

## 11. Missing safeguards

A collected flag in the order details.

## 12. Recommended remediation

Add an `IsCollected` field to OrderDetailsDto (additive), computed by the same rule as B05's handler check. Use it in CanRefundOrder.

## 13. Alternative approaches

A client call to check settlement status.

## 14. Required regression tests

Client test: a settled COD order can be refunded; an unsettled one cannot.

## 17. Acceptance criteria

The refund is offered exactly when the server allows it.
