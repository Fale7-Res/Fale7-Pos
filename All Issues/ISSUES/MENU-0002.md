No discard command exists in MenuEditorViewModel (grep).

## 4. Relevant historical evidence

Variants have no Active flag (MenuEntities ProductVariantEntity), so retiring a size is impossible except by removal.

## 5. Expected behaviour

Retiring a sold size is possible (deactivate) or refused with a clear message, never a stuck pending operation.

## 6. Actual code-supported behaviour

Every retry returns 500; the kept request survives restarts; the station cannot be locked or closed normally and several management screens refuse to open.

## 7. Root cause

(1) No variant deactivation; (2) FK violation unmapped → 500; (3) deterministic 5xx classified as "outcome unknown" ([API-0003](API-0003.md)); (4) no operator discard for management kept requests.

## 8. Business impact

Menu editor and station operations blocked until the retained file is deleted by hand.

## 9. Reproduction / failure scenario

Owner removes the "large" size of a product that has been sold → save.

## 10. Existing safeguards

Historical order lines protected by Restrict.

## 11. Missing safeguards

Variant Active flag; FK mapping to 409/422; discard path.

## 12. Recommended remediation

Add variant deactivation (keep row); map DbUpdateException for FK to a clear 409; let management screens discard a refused/unknown kept request after confirmation.

## 13. Alternative approaches

Soft-delete variants on removal.

## 14. Required regression tests

Remove a sold variant → 422/409 with message, no pending kept request; client test: 5xx then discard.
