# UI-0032 — The delivery board and the assign dialog told the driver to collect money from orders that were already paid

| Evidence date | 2026-11-07, b3071be + working tree (diff fingerprint 20154C06992970FB at Phase 0; Phase 1 edits listed per issue) |

**Evidence.** /api/delivery/board on the UI test server returned amountToCollectPiastres 9000 with paymentMethod card and paymentAlreadySettled true. DeliveryViewModel.BoardRow.AmountToCollectDisplay and DeliveryModalsView.xaml (assign dialog "للتحصيل") showed that raw amount, while the server opens no custody for it (DeliveryRules.DeliveryCashResponsibility). A driver told to collect 90 ج from a customer who already paid by card is a double charge.

**Fix.** DeliveryViewModel.CollectPiastres mirrors DeliveryCashResponsibility (cash always; other methods only while not settled); the board column and the assign dialog (AssignCollectDisplay, "لا شيء (مدفوع)") use it.

**Tests.** DeliveryCollectDisplayTests: RED against the pre-fix view model in the verification tree (3 failed: Expected "—", Actual "90.00 ج" for card/instapay/wallet paid), GREEN after; full client suite 246/246. **Native.** artifacts/claude-20261107/ui/phase1-dark/04-crop.png and phase1-light/04: paid card orders #0139/#0140 show "—" / "مدفوع". The assign dialog was not opened natively.
