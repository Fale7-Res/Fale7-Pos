## Remediation record — 2026-11-07, Phase 1b (Claude): shift screens and ambiguous success

### Shift screens

**Fix:** `ShiftsViewModel` open and close now go through durable requests (`shifts.open`, `shifts.close`).
- A retry re-sends the same request, both in the same session and after a restart.
- A pending close skips the manager-approval step, so it never spends a second approval.
- A recovered open or close is shown on the Shifts screen as a banner (`ShiftRecoveredBanner`) with a retry button (`ShiftRecoveredRetry`). A committed close leaves no open shift, so the close dialog can no longer reach it.
- The screen is registered in the recovery list.

**Files:**

### Residual

- **POS shift open/close** (`CashierViewModel.Shift` and `ShiftClose`) keeps its request id in memory until success. Retries in the same session are safe; it is not durable across a restart. This is a separate screen from the management Shifts screen.
- **POS recovered operations** do not raise `OperationStateChanged`, so a resolved POS operation does not yet clear the startup notice.
