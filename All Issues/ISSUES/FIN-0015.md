## 4. Relevant historical evidence

## 5. Expected behaviour

Negative values refused (422).

## 6. Actual code-supported behaviour

Negative fee = unapproved discount; negative discount/comp = unapproved surcharge; persisted values distort discount/comp reports.

## 7. Root cause

No sign validation of signed money at the API boundary.

## 8. Business impact

Over/under-charging via a crafted or buggy client; report distortion.

## 9. Reproduction / failure scenario

API call with DeliveryFeePiastres = -5000.

## 10. Existing safeguards

WinUI clients do not send negatives (not exhaustively verified).

## 11. Missing safeguards

Boundary validator.

## 12. Recommended remediation

Validate discount, fee, comp ≥ 0 (and within limits) before any computation.

## 13. Alternative approaches

No meaningful alternative identified.

Theory: each field −5000 → 422, no order row.
