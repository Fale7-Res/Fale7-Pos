# Independent source challenge: actor JSON casing differential

Baseline `c35816ecae49633674775dd32061c6ee92f94aaf`. Original printing/workflow reviewer, independent source trace requested by parent. **Disposition: source-traced authorization-bypass candidate; no countervailing actor overwrite/filter found.** This reviewer did not execute HTTP requests, initialize/migrate a database, authenticate to the active system, exercise a permissions write, or run a security plugin. Real-system exploit execution is **NOT VERIFIED**. Parent's separate in-memory binding/middleware harness should establish the remaining parser-default premise and its limits.

## Exact source-to-effect path

1. `src/Falah.Server/AuthenticationMiddleware.cs:30–59`: a valid Bearer session is resolved; the genuine user is placed in `HttpContext.Items["falah.actor"]`. Missing/revoked/expired/deactivated session fails401. This is real authentication, not anonymous access.
2. Same file `:69–80,86–88`: middleware compares declared actor claims via `FindActorMismatchAsync`; a found mismatch returns403, otherwise `_next` executes.
3. Same file `:91–119`: recognized actor strings are exactly `actorUserId`, `cashierId`, `createdByUserId`, `openedByUserId`, `reportedByUserId`. JSON is independently parsed with `JsonDocument`, and `TryGetProperty(field, ...)` checks those exact spellings. JSON properties such as `ActorUserId` are not explicitly enumerated or normalized. After inspection the body is rewound (`:125–130`), preserving the caller's JSON for later binding rather than replacing its actor.
4. `src/Falah.Application/Users/UserManagementRequests.cs:28–29`: `UpdateUserPermissionsRequest` has positional properties UserId, Grant, Revoke, ActorUserId, no custom binder or JSON-name attribute.
5. `src/Falah.Server/Program.cs:1951–1957`: POST `/api/users/{id}/permissions` binds that DTO, overwrites **only UserId** from path, then forwards request unchanged to `UpdateUserPermissionsHandler`. There is no HttpContext actor parameter or identity replacement. A case-insensitive body binder can therefore populate ActorUserId from the spelling omitted by the middleware comparison.
6. `src/Falah.Infrastructure/Users/UpdateUserPermissionsHandler.cs:28–35`: a Serializable transaction starts, then actor is independently loaded by **request.ActorUserId** and authorized for users_manage. This handler does not receive the authenticated user or HttpContext Items. `OrderMapper.cs:19–21` maps the supplied row's actual role/active/permissions.
7. `src/Falah.Domain/Authorization/ApprovalRegistry.cs:37–38,69–78`: an active actor with `all` or users_manage passes; no separate manager approval is required if that spoofed actor already has the permission.
8. Handler `:37–44` blocks modifying an owner target and prohibits granting permissions not held by the **supplied actor**. `UserManagementRules.cs:29–35` explicitly lets an actor with `all` grant any catalog permission; `PermissionCatalog.cs:17` includes all. These are useful guards against an honest lower-privileged actor, but do not bind actor to the session. Targeting the caller's own **non-owner** account avoids owner immutability; choosing an active privileged actor that holds all meets the existing no-escalation guard under the wrong identity.
9. Handler `:46–48,66–74`: target permissions are unioned with grant, saved, and committed; audit actor is the spoofed privileged row's Name. No later session identity assertion occurs. A subsequent `SessionService.ResolveAsync` (`SessionService.cs:49–54`) reloads the genuine user's current row, so changed permissions would be available to the same active session if persistence succeeds.

## Remaining binding premise and harness boundary

The project is an ASP.NET Core net8 Minimal API (`Falah.Server.csproj`). The endpoint uses normal complex-DTO parameter binding, no `[FromBody]` customization or custom `BindAsync`. Repository-wide searches of `src/**/*.cs` found **no** ConfigureHttpJsonOptions, AddJsonOptions, Microsoft.AspNetCore.Http.Json option registration, server PropertyNameCaseInsensitive override, JsonSourceGenerationOptions, JsonPropertyName, custom endpoint filter or request-DTO BindAsync. The only explicit PropertyNameCaseInsensitive found is unrelated PrintAgent configuration deserialization.

The proposed premise is the default web JSON binder accepting different property casing. This reviewer has not independently executed the default or production binder. Parent's in-memory harness should use **actual `Microsoft.AspNetCore.Http.Json.JsonOptions` defaults** and the baseline DTO, not merely assume options on a hand-written DTO. Show camelCase mismatched actor rejected403 and PascalCase/alternate-case actor forwarded and bound to the privileged ID. A test using only `JsonSerializerOptions(JsonSerializerDefaults.Web)` proves serializer semantics but should be labeled narrower than exercising the complete Minimal API request pipeline. No real DB handler execution is required to demonstrate the parser differential; source trace establishes the downstream authorization sink separately.

## Counterevidence searched

- `HttpContextActorExtensions.Actor/ActorId` exist at `AuthenticationMiddleware.cs:136–144`, but repository-wide search found no endpoint/handler call sites using those extensions; only the definitions and the extension's self-call. The stored genuine actor is not authoritative at the examined sink despite the comment asserting endpoints read it.
- No server endpoint filters, MapGroup authorization wrapper, custom JSON binding policy or per-request DTO actor rewrite was found. Global AuthenticationMiddleware is registered at `Program.cs:251`; normal request DTO binding occurs downstream. Exception middleware changes error responses, not actor identity.
- The user-permissions route's path overwrite protects the target ID consistency only. It does not overwrite ActorUserId.
- Domain no-privilege-escalation and owner immutability remain intact for the *wrong selected actor*. They reduce scenario choices but do not eliminate a non-owner target with an active `all` actor row.
- Knowing a privileged user ID is a realistic prerequisite: authenticated GET `/api/users` at `Program.cs:1838–1842` returns active IDs, roles and permissions. No actual enumeration was performed.
- Ordinary camelCase clients with mismatched actor are rejected; this is a parser-differential candidate, not a claim all actor checks are absent. Query `TryGetValue` uses a different collection mechanism; no query-name casing bypass is claimed.
- Valid low-privilege authentication and reachable backend are required. Shipped listener is localhost; same-machine callers remain in scope, while remote exploitability depends deployment binding/firewall and was not tested.
- Requiring a manager PIN at login or another operation does not authorize later body identity substitution. No manager approval field appears on UpdateUserPermissionsRequest.

## Safe hypothetical scenario, not executed

Use an existing low-privileged valid session L, a known **active** privileged user P holding all, and non-owner target L. Submit a permissions DTO with `ActorUserId` (PascalCase) naming P, Grant containing the valid permission all and empty Revoke; path names L. Under the default case-insensitive-binding premise, middleware fails to compare the alternate-spelled actor but the DTO receives P; handler authenticates permissions using P and modifies L. This describes a concrete privilege-escalation consequence conditional on parser behavior and ordinary SQL success. It is **not a statement that this operation was sent or succeeded against the user database**.

## Recommendation for later approved remediation

Derive command actor directly from authenticated server context before dispatch, remove/disbelieve body actor fields throughout all command entry points, and enforce a single authoritative identity downstream. Normalizing all JSON names in middleware is a limited stopgap and must reject conflicting duplicate-case fields; it does not address omitted actor fields or future DTO naming drift. Preserve manager approver identity as a separately validated second person. Add isolated route-level regression tests for all actor aliases, alternate casing, duplicate mixed-case fields, absent actor, body/path target consistency and legitimate manager approval. No implementation was made.
